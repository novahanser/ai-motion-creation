# 渲染与交付

## 1. 色彩与输出

- 写下工程工作空间、输出空间、位深、数据范围和 Alpha 解释。先渲代表性的亮部、暗部、平涂和半透明交界，再选最终编码。
- 需要复核像素时，先出高位深无损序列或无损中间文件。按目标平台明确配置编码、色彩标记和数据范围，回读成片核对。
- 小范围改动时可以只重渲受影响的整段。按统一格式拼接，查拼接点的帧数、方向、色彩和音频。

## 2. 声音

- 剪辑和标记用同一份基准音频。成片中的音轨从该基准或获准使用的无损母带输出。
- 如果替换音频或重编码，选几个开头、中段和结尾的明显起音比较实际偏移。按测到的偏移修正，并验证同步。

## 3. 字体和素材

- 渲染前核对缺失字体和替换后的文字宽度。小字在最终分辨率与码率下检查。
- 在字体与素材清单中记录发行页、使用范围、安装方式和所需署名。把可分发的文件随工程打包。
- 第三方插件同样记录版本和安装要求。接收方缺插件时，可以另出渲染版，并保留可改的工程结构。

## 4. 整理和收集

1. 保留整理前的版本。按用途给合成和图层命名，再整理未使用的素材。
2. 交付版尽量留编辑所需的文字层、曲线和合成结构。需要用渲染序列替代的部分，说明如何重渲和替换。
3. 收集实际引用且许可覆盖交付用途的文件。为要在接收方安装的插件、字体和大型序列列出依赖。
4. 在另一个目录重新打开收集的工程，查看素材引用、帧率、时长、音频和缺失项。选几帧与原工程比对。
5. 若提供轻量版，写清它缺少的序列、贴图或其他依赖，以及如何恢复。

## 5. 交付检查

- 在输出成片上核对切点、音画同步、文字、动效闪烁和调色板。
- 重开工程，确认交付要求中的文字、图层和曲线可编辑。
- 核对文件清单和署名。交接说明记录已验证的输出和接手时需要留意的地方。
